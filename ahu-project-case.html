Air Handling · Project Case

AHU 工程實戰：從 ASHRAE 混風範例到現場驗收

冬天外氣偏冷，辦公區有人喊冷、有人說悶；物業想先關小新風風門。工程師要先回答：外氣與回風實際混成什麼狀態？通風量是否仍達核准值？問題在混風、風量分配、盤管，還是測點？本文以 ASHRAE 的心理濕圖混風 Example 為計算起點，延伸成跨單位可執行的 AHU 專案流程。

依 ASHRAE Handbook—Fundamentals (SI) Chapter 1 Example 4 延伸｜案場協調與量測情境為教學演練，非實際工程紀錄

1. 案件任務：先把一句抱怨變成可簽認的工作範圍

模擬案場是一台服務辦公區的 AHU。冬季外氣偏冷時，使用者回報靠外牆區域有冷風感，會議室又有人反映空氣悶；物業值班人員提出先把外氣風門關小。使用單位希望當天改善，設計顧問則須確保最低通風量、舒適度與消防/控制功能不被犧牲；若需改造，停機只能安排週末。

這不是單一溫度設定問題：可能是外氣量、混風均勻度、支管風量、盤管輸出、送風擴散或感測器位置造成。專案經理先將症狀轉成測試方案與責任分工，不用降低通風量來掩蓋冷風感，也不在尚未定位故障前承諾換機或節能率。

2. 現勘與診斷：別讓控制畫面代替量測

第一次現勘不急著報設備價格。設計工程師、物業、TAB（測試、調整與平衡）廠商及控制廠商一起走風路與水路：從外氣百葉、混風箱、濾網、盤管、風機到最遠端支管；同時核對冰水閥、排水、電源、BMS 點位與檢修空間。用同一時鐘記錄風量、壓差、溫濕度、閥位、風機頻率及當時人數。

先把手冊計算輸入與案場待測值分清楚
項目Example 4 輸入／參考案場現勘狀態責任分工與下一步
外氣狀態4°C DB／2°C thermodynamic WB教學案場尚待現場測量，不能把手冊入口條件當實測值設計工程師與 TAB 確認測點；記錄儀器、時間、大氣壓力及遮蔽條件。

兩股風量外氣 2.0、回風 6.25 m³/s這是範例輸入，不是本案風量核准或量測紀錄TAB 廠商量外氣與回風支路；物業確認風門、濾網及風機當時運轉工況。
混合空氣心理濕圖讀值約 19.5°C DB／14.6°C thermodynamic WB僅在入口資料符合範例時可作預測基準於混風箱下游多點測量；若分布不均，先查混風與感測器位置。
盤管與送風須另外取得核准送風狀態及冷/熱水條件範例沒有提供盤管容量、送風目標或案場負荷設計者補足供水溫度/流量、出風目標及閥門控制資料後，再進行盤管選型。

現場觀察提供的是假說，不是結論：例如「外氣風門開 25%」不等於外氣量正好是總風量的 25%；「回風口很暖」也不等於混風箱內混合均勻。診斷紀錄要標註儀器、校正狀態、測點位置、工況和不確定性，並把手冊示例、現場實測與工程判斷三種資料明確分開。

決策閘門 A｜是否真的要換整台？查箱體腐蝕與漏風、盤管洩漏／污堵、風機與馬達狀態、零件供應、可拆換路徑、維修空間及總生命週期成本。若箱體、盤管可用，主要故障在風門、風機與平衡，先比較局部改造；若結構、盤管或箱體已無法達到性能及衛生要求，再提出整機汰換選項。

3. 跨單位協調：把「誰做、誰供資料、誰放行」寫出來

AHU 不是單一廠商可以獨立完成的設備。設計顧問若只把風量交給空調廠，現場仍可能因配電容量不足、屋頂吊裝路線不通、冰水停機未核准或消防聯鎖沒人負責而卡住。專案啟動時建立 RACI（執行、負責、諮詢、知會）或至少一張介面責任表，會議結論要有負責人、期限及文件版本。

4. 用 ASHRAE Example 4 做混風計算，再問現場該怎麼辦

ASHRAE 的計算範例不是 AHU 全案設計；它解決的是混風箱中兩股濕空氣混合後的狀態。本案保留範例入口條件作為心理濕圖計算基準，再把結果拿去規劃現場測試。風量是否合格、混風是否均勻，以及下游盤管容量，仍需另外取得案場資料。

手冊混風計算的已知條件（101.325 kPa 心理濕圖）

外氣2.00 m³/s4°C DB／2°C thermodynamic WB0.789 m³/kgda
回風6.25 m³/s25°C DB／50% RH0.858 m³/kgda

降低外氣風門混合空氣會變暖，但可能低於核准最低外氣量；舒適改善不能取代通風合規。物業確認核准風量；TAB 實測；設計顧問判斷通風要求。風門調整前後外氣量、總送風量與操作時段。
混風溫度偏低可能是入口狀態不同、風門洩漏/失準、混合不均，或感測器偏差。TAB 與控制商共用已校正儀器及同一測點圖。外氣、回風、混風箱多點溫濕度及風量同步紀錄。
室內仍有冷風感不必然表示整股混風溫度錯；送風口位置、風量分配、射程與占用也可能有影響。空調設計、物業、使用單位共同確認代表區域。送風口風量/方向、區域溫度及時段、使用者位置與回饋。
盤管加熱/冷卻能力混合狀態只定義盤管入口之一；未有出口目標、介質與負荷不能算盤管容量。設計者提供供風目標；設備商依核准工況選型。盤管選型表、供回水溫度/流量、閥門與出風狀態。
決策先驗證兩股風量、入口狀態及混風分布；再決定修風門、感測器、盤管或風量平衡。除非結構/設備檢查支持汰換，不從一次心理濕圖計算直接推導換機。

逐步計算：先轉成乾空氣質量流率

外氣乾空氣質量流率：ṁoa = V̇oa ÷ voa = 2 ÷ 0.789 = 2.535 kgda/s
回風乾空氣質量流率：ṁra = V̇ra ÷ vra = 6.25 ÷ 0.858 = 7.284 kgda/s
總乾空氣質量流率：ṁmix = 2.535 + 7.284 = 9.819 kgda/s
外氣乾空氣質量占比：2.535 ÷ 9.819 = 0.258 ≈ 25.8%
心理濕圖分點比例：ṁra ÷ ṁmix = 7.284 ÷ 9.819 = 0.742

體積流率提供於各股氣流入口狀態，因此先用各自比體積換算乾空氣質量流率，再做混合狀態平衡。心理濕圖上混合點沿兩個入口狀態連線定位；圖表讀值屬工程圖解近似值。

手冊心理濕圖結果：混合空氣約 19.5°C DB／14.6°C thermodynamic WB
若錯用體積加權平均乾球：[(2 × 4) + (6.25 × 25)] ÷ 8.25 = 19.91°C

工程解讀：不能把風門開度或體積比例直接當成乾空氣質量比例；更不能只用兩個乾球溫度的算術平均判斷混風。要以入口空氣狀態、質量流率、含濕量與焓平衡求混合狀態，並在現場驗證。

在本案，這個 19.5°C DB／14.6°C thermodynamic WB 是「混風箱入口資料符合範例時」的參考盤管入口狀態，不是供風設定值，也不是盤管容量。下一步由設計者定義冬季送風目標與濕度要求，再確認盤管介質、供回水溫差、可用流量、盤管壓降、閥門權度及風機熱；沒有這些條件就不能由 Example 4 計出加熱/冷卻 kW。

不能為了舒適而任意關小新風：如果混風後的冷風感明顯，先查混風均勻度、送風口射程、末端風量、盤管控制及區域負荷；外氣量若需改變，必須經設計與業主依核准通風條件重新確認，並由 TAB 實測。

5. 採購與送審：把「同等品」鎖定在同一工作點

不能把手冊範例兩股入口體積流率相加的 8.25 m³/s 直接抄成 AHU 風機選型點。設計團隊需按風機所在斷面的空氣狀態與密度，確認設備實際風量，再連同髒濾網條件下的外部靜壓列入資料表。送審要用同一設計工況比較，並核對馬達負載裕度、效率、噪音、設備尺寸重量及既有吊裝路徑。

AHU 改造採購送審的實用清單
送審資料審查重點核准前的退件條件
風機選型與曲線設計風量、總/外部靜壓、效率、功率、轉速、噪音及工作區域。只報「最大風量」或自由送風量，沒有對應工作點。
風機/VFD/馬達電源、額定電流、絕緣、諧波/EMC 要求、最低轉速、旁路與保護。設備電流超過既有饋線能力，或維修隔離方式未定。
外氣風門及致動器有效面積、漏風等級、扭矩、失效位置、連桿、位置回授及實測方式。只有 0–100% 命令，無法在現場證明外氣實際流量。
外形/檢修圖尺寸、重量、門片開啟、濾網/風機抽出距離、吊點與維修通道。無法通過既有通道、妨礙閥件操作或沒有安全檢修空間。

送審會議的輸出不只是「核准」印章：要有已接受偏差、未決項目、影響及期限。涉及風機型號、馬達功率、濾網終阻力、控制方式或箱體改造的偏差，須評估是否改變風量、電力、噪音、消防、工期與保固，必要時更新圖面與價格。

6. 施工與切換：真正容易延誤的是介面和復原

假設本案週六 22:00 至週一 05:00 才能停機，實際窗口由業主核定。總包把施工拆成工作包並逐項簽認：租戶通知與門禁、屋頂吊裝許可、吊車/交通管制、電源上鎖掛牌（LOTO）、冰水隔離與排水、風管保護、舊風機拆裝、控制點線路標記、清潔與復原、消防/防水檢查、試運轉及恢復服務。

  1. 停機前一週：設備及材料到場驗收；核對尺寸/重量、吊裝路線、吊點、臨時防雨、備用皮帶/軸承/致動器，完成施工許可與風險告知。
  2. 停機前一天：存檔 BMS 程式與參數、標記線號/風門方向、記錄基線功率及設定；通知租戶和保全，確認替代冷房或不能停機的區域。
  3. 隔離後拆裝：由授權人員隔離電源和水路；開啟風管前封存防塵，排水作業保護天花與裝修。發現圖實不符、腐蝕、保溫含水或防火閥干涉時先停下走 RFI，不現場擅自改管。
  4. 復機前檢查：檢查緊固、對心/皮帶、旋向、接地、隔振、護罩、門板密封、排水水封及閥門復位；控制與消防聯鎖未完成，不交由一般操作人員啟動。
週末施工的風險控制：指定唯一停機/復機指揮人；每個隔離點有掛牌與復歸簽名；吊裝、電氣和冷水作業各自有合格負責人。預留故障回復時間與備品，不把「凌晨前一定復機」當作安全控制措施。

7. 控制整合：先寫出序列，再接線、再測點

本案保留既有 BMS，但新增/修改的控制必須先形成核准序列。啟動時確認消防允許、手自動狀態及必要聯鎖；風機啟動後以實際風量或經驗證的靜壓控制 VFD；外氣風門依核定最低通風量調節，不把開度百分比當風量；冰水閥依送風溫度/除濕需求調節；濾網壓差告警依廠商終阻力設定。若風量感測故障、風機故障或消防停機，按核准的安全狀態停機/關閉風門並產生警報。

控制整合常見的協調問題是「點位表有了，但沒人知道誰供感測器、誰拉線、誰負責校正」。在送審階段逐點指定設備端子、BMS 控制器、線纜/供電、網路地址、圖形畫面、趨勢及測試責任；消防訊號由消防專業承包商依核准介面測試，不以 BMS 畫面變色代替安全功能見證。

8. 試運轉與驗收：每個承諾都要有測法和簽名欄

試運轉不是「風機有轉、冷氣有冷」。先完成單機檢查，再做 TAB 與功能性能測試，最後由業主/物業見證整合功能。下列數值是從手冊混風計算轉成的測試參考條件，不是實際案場保證值；真實工程的允差與最低通風量必須在採購前由設計者依量測不確定度、適用規範及核准設計明訂。

  2. 先測單機：旋向、轉速、皮帶/軸承、振動、電流、護罩、排水與箱體密封。
  3. 再測系統：同步量兩股進氣及混風段多點狀態，完成支管及末端 TAB，封存風門與末端初始閥位。
  4. 測功能序列：啟停、風量調節、外氣、冰水閥、濾網警報、故障及手自動切換。
  5. 做整合見證：由消防/控制/物業共同測試消防停機、警報傳遞及安全復歸。
  6. 列 punch list：每個缺失指定責任人、完成期限、複驗證據；未通過項目不可標成完成。

9. 移交後才知道改造有沒有真正成功

完成驗收不代表工作結束。業主指定一位營運負責人接收可操作的資料，並約定 2–4 週後回訪（本案示例）：在相近占用與天候下比較室溫/濕度、外氣量、風機功率、風機運轉時數、濾網壓差及使用者回饋。若天候或占用不同，先標註條件，不把未校正的電費差額直接宣稱為節能成果。

10. 工程師帶走的不是答案，而是一條可重複的流程

AHU 改善專案的八個決策閘門
階段必須回答的問題進入下一階段的證據
1｜定義需求誰遇到什麼問題、何時、哪些區域？成功由誰判定？簽認需求表、停機限制、驗收責任人。
2｜建立基線現場風量、外氣、壓差、電力、溫濕度與圖說是否一致？具測點、工況、儀器和校正資料的調查報告。
3｜比較方案修理、改造、汰換各自的性能、工期、風險與總成本？業主核准選項及預算，並記錄選擇理由。
4｜整合設計機械、電氣、控制、消防、結構、租戶營運的介面是否閉合？核准圖說、設備資料表、點表、控制序列及測試計畫。
5｜準備施工設備到場、吊裝、隔離、復原及臨時服務可否按窗口完成？預施工會議紀錄、工作許可、備品與回復計畫。
6｜施工查驗是否按核准版施工？是否有未核准偏差或隱蔽工程問題？檢查紀錄、材料證明、照片、更新 RFI/竣工圖。
7｜測試驗收風量、外氣、控制、消防和舒適是否以約定方法通過？TAB、功能性能測試、見證簽名及 punch list 關閉。
8｜移交追蹤營運人員能否管理？實際效果是否維持？操作訓練、備份、基線報告、回訪與季節性調校。

工程實務的價值不只在算出風量或盤管容量，而在於讓所有假設能被追蹤、每個介面有人負責、變更有紀錄、驗收有證據。當設計計算、採購資料、施工品質、控制程式與營運人員講的是同一組數字，AHU 才算真正交付。
